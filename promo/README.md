# МПМЕК — обзор сайта в одном морфе

Зацикленный ролик 1440×1440, 60 fps, 14 с: 7 тактов при 120 BPM, на каждую долю что-то происходит. Это обзор [ribbletech.online](https://ribbletech.online/), сайта Могилів-Подільського монтажно-економічного фахового коледжу, в том порядке, в каком его проходит студент. Все надписи взяты с сайта и из кабинета тестового аккаунта `student`.

Готовое видео: `out/mpmek-loop.mp4`. Последний кадр совпадает с первым, включая позицию и скорость курсора.

Чего на сайте нет и чем это заменено:

- **Play/pause.** Его заменяет морф иконки «Перейти до курсу» в часы.
- **Перетаскивание прогресса.** На сайте полоса прогресса семестра только показывается. В ролике её тянут, и номер недели («N-й навчальний тиждень (Чисельник/Знаменник)») считается из реального календаря семестра.
- **Тост.** У студента сайт тостов не показывает, поэтому в финале открывается раздел «Новини» с реальной новостью.
- **Поиск.** ⌘K на сайте ищет только по шести разделам, поэтому набирается название раздела, а не специальности.

Имён преподавателей и студентов в кадре нет. «Пʼятниця» написана с апострофом (на сайте «Пятниця»).

## Как устроено

- `index.html`: один файл, `seek(t)` выставляет все стили как чистую функцию времени. Нет CSS-переходов, таймеров и состояния между кадрами.
- **Пружины.** Это замкнутые решения (переходная характеристика пружины). Если значение меняет цель много раз, оно равно сумме пружин, по одной на каждую смену. Учитывается и хвост прошлого цикла, поэтому `f(0) = f(14)`.
- **Форма.** Одна форма меняет размер, скругление и цвет. Вместе с ней живут ещё два элемента: ручка (ползунок → кноб переключателя → индикатор меню → отметка «сегодня» → клавиша ⌘K → выделение в поиске → значок новости) и полоса прогресса. Края индикатора едут на разных пружинах, поэтому ведущий край растягивается вперёд.
- **Перетаскивание.** Пока кнопка зажата, значение считается из позиции курсора, за краем полоса тянется как резинка. После отпускания значение пружинит из той точки, где его отпустили.
- **Камера.** Масштабируется так, чтобы каждое состояние заполняло кадр. `will-change` нигде нет.
- **Звук.** `audio.py` находит сетку битов трека (автокорреляция онсетов, фаза, сильная доля по хлопкам на 2 и 4, подгонка по бочке с точностью до сэмпла). UI-звуки синтезируются, и каждый ставится так, чтобы его измеренный пик попал на свою долю.
- **Рендер.** `render.mjs` снимает Playwright'ом 240 подкадров в секунду. ffmpeg `tmix` склеивает по 4 подкадра в кадр 60 fps (размытие в движении).

```bash
./build.sh            # npm install, трек, стоп-кадры по битам, рендер, звук, mp4
```

Нужны Node 18+, Python 3 с numpy, ffmpeg и Chromium (путь задаётся через `CHROMIUM`, по умолчанию `/opt/pw-browsers/chromium`).
